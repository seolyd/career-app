# 데이터

## 확인된 사실: 현재 FMP 계정으로는 안 됩니다

설계 중 실제로 호출해서 확인한 결과입니다.

| FMP 엔드포인트 | 결과 |
| --- | --- |
| `commodities-quote` (CLUSD 시세) | 거부 — 상위 플랜 필요 |
| `batch-quote` (시세 일괄) | 거부 — **Premium 이상** 필요 |
| `intraday-5-min` (5분봉) | 거부 — **Starter 이상** 필요 |
| `crypto-news` (뉴스) | 거부 — **Starter 이상** 필요 |
| `commodities-list` (종목 목록) | **성공** |

즉 지금 연결된 FMP 계정은 최하위 플랜이고, **이 앱에 필요한 시세·5분봉·뉴스가 전부
막혀 있습니다.** 종목 심볼(`CLUSD`=원유, `GCUSD`=금, `DXUSD`=달러지수, `BZUSD`=브렌트)은
확인됐으니 플랜만 올리면 바로 쓸 수 있습니다.

그래서 설계를 이렇게 잡습니다: **프로바이더 어댑터 층을 두고, 지금 무료로 되는
조합을 기본값으로 쓰되, FMP는 한 줄 설정으로 켜지는 자리에 남겨둡니다.**

## 프로바이더 구성

### 기본값 (지금 당장, 추가 비용 0)

| 데이터 | 종목 | 소스 | 비고 |
| --- | --- | --- | --- |
| 시세·캔들 | **BTC** | Binance 공개 REST/WS | 무료·무키·CORS 허용. `/api/v3/klines`로 1분봉, 웹소켓으로 실시간 틱. 이 앱에서 가장 좋은 데이터 |
| 펀딩비·미결제약정 | **BTC** | Binance Futures 공개 API | 문맥 디텍터 재료. 역시 무료 |
| 시세·캔들 | **CL, GC** | Yahoo 차트 엔드포인트 (`query1.finance.yahoo.com/v8/finance/chart/CL=F`) | 무료, 5분봉 제공. **비공식 API**라 언제든 막힐 수 있음 → 반드시 프록시 뒤에 두고 폴백 준비 |
| 문맥 (DXY) | **GC** | 같은 Yahoo 엔드포인트 (`DX-Y.NYB`) | |
| 뉴스 | 전 종목 | RSS 수집 (서버에서 파싱) | Reuters 상품/에너지, OilPrice, Kitco, CoinDesk, CoinTelegraph 등. `fast-xml-parser` |

### 폴백 체인

비공식 소스는 죽습니다. 그래서 `registry.ts`가 종목별로 순서를 갖습니다.

```
CL:  yahoo → (FMP, 플랜 있으면) → stooq(지연 EOD) → 캐시 + "데이터 지연" 표시
GC:  yahoo → (FMP) → stooq → 캐시
BTC: binance → yahoo → 캐시
```

마지막 단계가 "에러 화면"이 아니라 **"캐시된 값 + 몇 분 전인지 표시"**인 게 중요합니다.
데이터가 끊겼다고 앱이 빈 화면이 되면 안 되고, 반대로 오래된 값을 현재가인 척
보여줘도 안 됩니다.

### 업그레이드 경로

FMP **Starter**로 올리면 5분봉과 뉴스가 열려서 CL·GC의 비공식 의존을 끊을 수
있습니다. **Premium**이면 실시간 시세까지 한 제공자로 통합됩니다. 어댑터가 있으니
`registry.ts`의 순서만 바꾸면 되고 앱 코드는 건드리지 않습니다.

대안 제공자(같은 어댑터 자리에 들어감): Twelve Data(무료 800회/일), Polygon,
Tiingo, Alpha Vantage.

## 서버리스 API

세 개면 충분합니다. 서버는 판단하지 않고 중계·정규화·캐시만 합니다.

```
GET /api/quote?symbols=CL,GC,BTC
GET /api/candles?symbol=CL&interval=5m&range=5d
GET /api/news?symbol=CL&limit=30
```

무엇을 쓰든 응답 모양은 고정입니다(`docs/MODEL.md`). 응답에는 항상 `source`와
`fetchedAt`이 들어가고, 앱은 그걸 화면에 표시합니다.

## 갱신·캐시 정책

| 데이터 | 클라이언트 | 서버 엣지 캐시 |
| --- | --- | --- |
| 시세 | 포그라운드 15초 (설정에서 5~30초), 백그라운드 중단 | `s-maxage=10, stale-while-revalidate=30` |
| 1m·5m 캔들 | 봉 마감 시각에 맞춰 | `s-maxage=30, swr=120` |
| 15m·1H 캔들 | 2분 | `s-maxage=120` |
| 일봉 | 5분 | `s-maxage=300, swr=1800` |
| 뉴스 | 60초 | `s-maxage=60, swr=300` |
| BTC 펀딩·OI | 5분 | `s-maxage=300` |

**엣지 캐시가 곧 비용 통제입니다.** 15초마다 시세를 부르는 클라이언트가 여럿이어도
엣지에서 10초 캐시가 걸리므로 상위 제공자 호출은 초당 0.1회로 수렴합니다.

**stale-while-revalidate**를 쓰는 이유: 캐시가 만료돼도 사용자는 즉시 이전 값을 받고,
갱신은 뒤에서 일어납니다. 화면에 스피너가 뜰 일이 없습니다.

**클라이언트 쪽도 같은 패턴** — 앱을 열면 IndexedDB의 마지막 값으로 즉시 그리고,
동시에 네트워크로 갱신합니다. 지하철에서 앱을 열어도 화면이 비지 않습니다.

**폴링 중단 조건** — `document.visibilityState !== 'visible'`, 배터리 절약 모드,
오프라인. 아이폰에서 백그라운드 폴링은 어차피 OS가 죽입니다.

## 뉴스를 "실시간"으로 만드는 법

RSS는 보통 5~15분 지연됩니다. 세 가지로 줄입니다.

1. **소스를 여럿 섞습니다.** 같은 사건을 다른 매체가 다른 시각에 냅니다. 중복은
   제목 유사도로 접습니다.
2. **예정 이벤트를 뉴스보다 먼저 보여줍니다.** EIA 재고는 언제 나올지 이미 알고
   있습니다. "2시간 12분 뒤"가 발표 후 기사보다 트레이딩에 유용합니다.
3. **종목 라우팅** — 수집한 항목을 키워드로 세 종목에 배분합니다. (원유: OPEC,
   inventory, EIA, barrel, refinery / 금: Fed, FOMC, CPI, yield, dollar, bullion /
   BTC: ETF, halving, SEC, on-chain 등) 어디에도 안 붙으면 "매크로"로 셋 다에 보냅니다.

원문 본문은 앱에 복제하지 않습니다 — 저작권 문제이고, RSS가 주는 제목·요약·링크까지만
저장한 뒤 읽기는 원문으로 보냅니다.

## 선물 특유의 함정

**연속물 롤오버.** `CL=F`는 근월물 연속 시리즈라 만기 교체 때 가격이 점프합니다.
지표가 그 갭을 실제 움직임으로 착각해서 ATR이 튀고 가짜 돌파 신호가 납니다.
대응: 롤 날짜를 알고 있다가 (a) 차트에 세로선으로 표시하고 (b) 갭 봉을 지표 계산에서
제외하거나 조정합니다. 금(`GC=F`)도 같습니다. BTC는 현물이라 해당 없음.

**거래량의 의미.** 연속물의 거래량은 근월물 거래량이라 롤 주간에 왜곡됩니다.
참여 디텍터가 롤 주간에 이상한 값을 내면 이걸 의심해야 합니다.

**"현재가"가 여럿입니다.** 선물의 정산가·최종체결가·호가중간값이 다르고, 제공자마다
뭘 주는지 다릅니다. 정규화 층에서 어느 것인지 명시하고, 앱에 출처를 표시합니다.

**주말.** 원유·금은 주말에 값이 멈춥니다. "지난 금요일 종가"를 현재가처럼 보여주지
않도록 세션 상태를 항상 함께 계산합니다. BTC만 주말에 살아 있고, 대신 주말 거래량이
얇아서 변동성 게이트가 자연히 걸러줍니다.
