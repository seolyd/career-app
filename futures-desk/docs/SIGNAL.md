# 시그널 엔진

단타(스캘핑) 롱/숏 진입 자리를 감지하는 장치. "어떤 장치가 적절한가"에 대한 답입니다.

## 먼저, 하지 않을 것

설계를 정하기 전에 흔한 실패부터 배제합니다.

**지표를 많이 얹지 않습니다.** RSI + 스토캐스틱 + CCI + MFI + Williams %R을 다 넣으면
지표 다섯 개가 아니라 **같은 정보를 다섯 번 세는 것**입니다. 전부 가격 모멘텀의
변형이라 서로 강하게 상관돼 있고, 합산하면 한 가지 관점에 5배 가중치를 주는 꼴이
됩니다. 서로 **다른 축**을 재는 소수의 디텍터가 낫습니다.

**머신러닝을 v1에 쓰지 않습니다.** 학습시킬 자기 데이터가 아직 0건이고, 틀렸을 때
왜 틀렸는지 설명할 수 없고, 금융 시계열에서 과적합은 기본값입니다. 규칙 기반으로
6개월치 채점 기록을 쌓은 다음에 논의할 문제입니다.

**과매수/과매도를 단순 반전 신호로 쓰지 않습니다.** 추세장에서 RSI 70은 매도
신호가 아니라 강세의 증거입니다. 이 하나가 초보 시그널 시스템이 돈을 잃는 가장
흔한 이유입니다.

**자동 주문 연동을 하지 않습니다.** 시그널과 집행 사이에는 사람이 있어야 합니다.

## 구조

```
        캔들 (5분봉 마감 시에만)
              │
    ┌─────────▼─────────┐
    │ 0. 게이트          │  ─── 하나라도 걸리면 → WAIT (점수 무시)
    │  세션·변동성·이벤트 │
    └─────────┬─────────┘
    ┌─────────▼─────────┐
    │ 1. 레짐 판별       │  ─── 추세 / 박스 / 스퀴즈
    └─────────┬─────────┘      → 디텍터 가중치를 바꿈
    ┌─────────▼─────────┐
    │ 2. 디텍터 6개      │  ─── 각각 -1.0 ~ +1.0
    │  추세 모멘텀 변동성 │
    │  참여 구조 문맥     │
    └─────────┬─────────┘
    ┌─────────▼─────────┐
    │ 3. 합성            │  ─── Σ(가중치 × 점수) → -100 ~ +100
    └─────────┬─────────┘
    ┌─────────▼─────────┐
    │ 4. 거래 계획       │  ─── 진입·손절·목표·R:R, 손익비 미달이면 폐기
    └─────────┬─────────┘
    ┌─────────▼─────────┐
    │ 5. 저장 + 채점     │  ─── 스냅샷 저장, 이후 캔들로 자동 채점
    └───────────────────┘
```

---

## 0단계 — 게이트: 언제 거래하지 않을 것인가

가장 먼저 만들고 가장 중요한 부분입니다. **좋은 진입을 찾는 것보다 나쁜 환경을
빼는 것이 수익에 더 크게 기여합니다.** 게이트에 하나라도 걸리면 점수가 몇 점이든
시그널을 내지 않고, 이유를 화면에 적습니다.

| 게이트 | 판정 | 왜 |
| --- | --- | --- |
| **세션** | 종목별 유동성 시간대 밖 | 원유를 한국 오후에 단타하면 호가가 비어 있습니다. 슬리피지가 기대수익을 먹습니다 |
| **변동성** | ATR(14, 5m)이 최근 20일 분포의 30퍼센타일 미만 | 스캘핑은 변동성이 재료입니다. 안 움직이면 수수료만 냅니다 |
| **이벤트** | 예정 발표 ±N분 | 지표는 발표 직전 상황을 설명하지 못합니다. 발표 순간의 갭에 손절이 관통당합니다 |
| **데이터** | 마지막 봉이 N분 이상 오래됨, 또는 비정상 갭 | 틀린 데이터로 낸 시그널이 제일 위험합니다 |
| **손익비** | 계산된 R:R < 1.2 | 맞아도 남는 게 없는 자리는 자리가 아닙니다 (4단계에서 판정) |

**이벤트 블랙아웃 (종목별)**

| 종목 | 이벤트 | 시각(KST 기준) | 중단 |
| --- | --- | --- | --- |
| 원유 | EIA 주간 원유재고 | 수 23:30 (서머타임 22:30) | 전 15분 / 후 15분 |
| 원유 | API 재고(비공식) | 화 05:30 | 전후 10분 |
| 원유 | OPEC+ 회의, 베이커휴즈 리그카운트 | 부정기 / 금 02:00 | 10분 / 5분 |
| 금 | FOMC 성명·기자회견, CPI, 비농업고용 | 부정기 | 전 30분 / 후 30분 |
| 금 | 파월·주요 연준 인사 발언 | 부정기 | 전후 15분 |
| BTC | FOMC·CPI(매크로 연동), 분기 옵션 만기 | 부정기 / 분기말 금 | 15분 |

v1은 반복 일정을 하드코딩 + 부정기 이벤트를 설정에서 수동 입력합니다.
v3에서 경제지표 캘린더 API를 붙입니다.

## 1단계 — 레짐: 지금이 어떤 장인가

**같은 지표가 장에 따라 정반대의 의미를 가집니다.** 추세장에서 "볼린저 상단
터치"는 강세의 증거지만 박스장에서는 매도 자리입니다. 그래서 디텍터를 돌리기 전에
장을 먼저 분류하고, 분류 결과가 **디텍터의 가중치를 바꿉니다.** 이게 이 설계의
핵심입니다.

판별 (15분봉 기준):

| 레짐 | 조건 |
| --- | --- |
| `TREND_UP` | ADX(14) ≥ 25 그리고 EMA50 기울기 > 0 그리고 +DI > -DI |
| `TREND_DOWN` | ADX(14) ≥ 25 그리고 EMA50 기울기 < 0 그리고 -DI > +DI |
| `SQUEEZE` | 볼린저 밴드폭이 최근 100봉 분포의 20퍼센타일 미만 (돌파 대기) |
| `RANGE` | 나머지 — ADX < 20, 밴드폭 보통 |

레짐별 가중치 (`signal/weights.ts`):

| 디텍터 | TREND | RANGE | SQUEEZE |
| --- | --- | --- | --- |
| 추세 | **0.30** | 0.05 | 0.10 |
| 모멘텀 | 0.15 | **0.25** | 0.10 |
| 변동성·돌파 | 0.10 | 0.05 | **0.35** |
| 참여(거래량) | 0.20 | 0.15 | **0.25** |
| 구조·위치 | 0.15 | **0.35** | 0.10 |
| 문맥 | 0.10 | 0.15 | 0.10 |

- **TREND** — 눌림목에서 추세 방향으로. 역추세 신호는 사실상 무시됩니다.
- **RANGE** — 박스 상·하단에서 역방향으로. 구조(레벨)와 모멘텀 다이버전스가 주인공.
- **SQUEEZE** — 방향을 예측하지 않고 **돌파가 일어나면** 따라붙습니다. 거래량이 함께
  터지지 않는 돌파는 페이크이므로 참여 가중치도 같이 올라갑니다.

이 표는 처음엔 감으로 정하고, 5단계의 채점 데이터가 쌓이면 근거를 갖고 고칩니다.

## 2단계 — 디텍터 여섯

각각 캔들과 지표만 보고 `-1.0`(강한 숏) ~ `+1.0`(강한 롱)을 냅니다. 서로를 모릅니다.

### 1) 추세 — "가격이 구조적으로 어디로 가는가"
- EMA 9 / 21 / 50 정렬 상태 (9>21>50이면 만점, 뒤엉키면 0)
- EMA50 기울기를 ATR로 정규화 (종목 간 비교 가능하게)
- MACD 히스토그램의 부호와 **확대/축소 여부** (히스토그램이 줄고 있으면 추세 힘이 빠지는 것)

### 2) 모멘텀 — "힘이 붙고 있는가"
- RSI(14)의 **50선 통과**를 주 신호로 씀 (70/30을 반전 신호로 쓰지 않음)
- RSI 다이버전스 — 가격은 신고점인데 RSI는 낮아지면 감점. 되돌림을 미리 경고하는 몇 안 되는 신호
- Stochastic RSI는 **타이밍 보조**로만 — 방향은 위에서 이미 정해졌고, 이건 "지금 진입인가
  한 봉 기다릴 것인가"에만 관여

### 3) 변동성·돌파 — "무언가 시작됐는가"
- 볼린저/켈트너 스퀴즈 해제 (밴드가 켈트너 안으로 수축했다가 밖으로 확장하는 순간)
- 돈치안(20) 전고·전저 돌파
- ATR 확장률 — 직전 봉 대비 변동성이 붙고 있는가

### 4) 참여(거래량) — "돈이 실렸는가"
- 거래량 z-score (최근 20봉 평균 대비 표준편차 배수)
- OBV 기울기 — 가격과 같은 방향인가
- **거래량 없는 가격 움직임은 감점입니다.** 페이크 돌파를 걸러내는 가장 값싼 장치

### 5) 구조·위치 — "지금 가격이 어디 서 있는가"
스캘핑에서 손절·목표 숫자가 실제로 나오는 곳입니다.
- 세션 VWAP 대비 위치를 **ATR 단위**로 (VWAP 위 0.3 ATR 등)
- 전일 고/저, 당일 고/저, 야간장 범위
- 피벗 포인트 (Camarilla — 단타 목표가로 적합)
- 라운드 넘버 (원유 $63.00, 금 $3,700, BTC $95,000) — 실제로 호가가 몰립니다
- 레벨 **바로 앞에서의 순방향 진입은 감점**합니다. 저항 5틱 앞 롱은 좋은 자리가 아닙니다

### 6) 문맥 — 종목마다 다른 축
같은 코드가 아니라 종목별로 다른 입력을 봅니다. 이게 "세 종목 전용 앱"의 이점입니다.

| 종목 | 문맥 입력 |
| --- | --- |
| **원유 CL** | 브렌트-WTI 스프레드 이상 확대 / 천연가스·가솔린 동조 / 재고 발표 주간 여부 |
| **금 GC** | **DXY 역상관** — 달러가 반대로 강하게 움직이면 금 롱 감점. 미 10년물 실질금리 방향. 금은 순수 기술적 종목이 아니라 달러·금리의 함수입니다 |
| **BTC** | **펀딩비** — 과열(고펀딩)은 청산 연료라 롱 가점이 아니라 감점. **미결제약정(OI)** 변화 — 가격↑+OI↑는 신규 매수, 가격↑+OI↓는 숏커버(약함). 롱숏 비율. 전부 Binance 공개 API로 무료 |

## 3단계 — 합성

```
raw   = Σ (weight[regime][detector] × detector.score)     // -1.0 ~ +1.0
score = round(raw × 100)                                   // -100 ~ +100
```

| |score| | 판정 |
| --- | --- |
| 0 ~ 29 | `WAIT` — 신호 아님 |
| 30 ~ 59 | `WEAK` — 관망 또는 소액. 화면에는 표시하되 알림은 보내지 않음 |
| 60 ~ 100 | `SIGNAL` — 방향은 부호, 확신도는 절대값 |

**쿨다운** — 같은 종목·같은 방향의 신규 시그널은 3봉(5분봉 기준 15분) 동안 내지 않습니다.
없으면 한 추세에서 같은 신호가 여덟 번 뜹니다.

**계산 시점** — **봉이 마감될 때만** 계산합니다. 미완성 봉으로 계산하면 지표가
1초마다 바뀌면서 신호가 켜졌다 꺼졌다 깜빡입니다. 실제로 백테스트와 결과가 달라지는
지점이기도 합니다.

## 4단계 — 거래 계획

시그널은 방향만 주는 게 아니라 **실행 가능한 숫자**를 줍니다. 여기까지 나와야 시그널입니다.

```
진입 구간 = 현재가 ± 0.25 ATR        // 추격 진입 방지. 이 구간을 벗어나면 그 시그널은 끝
손절     = max(직전 스윙 저/고점, 1.2 × ATR(14,5m))   // 둘 중 더 먼 쪽
           → 구조 기반이 원칙이되, 노이즈에 털리지 않을 최소 폭을 보장
R        = |진입 - 손절|
목표1    = 진입 ± 1.0R   또는 다음 구조 레벨 중 가까운 쪽
목표2    = 진입 ± 2.0R   또는 그 다음 레벨
유효시간 = 6봉 (5분봉 기준 30분) 경과 시 만료
```

**손익비 < 1.2면 시그널을 폐기합니다.** 점수가 80점이어도, 바로 위에 저항이 있어
목표까지 0.4R밖에 못 가면 좋은 자리가 아닙니다.

**포지션 사이즈 힌트** — 설정의 "1회 리스크 %"와 손절폭으로 역산해서
"이 자리는 계좌의 1%를 걸면 X 단위" 정도를 보여줍니다. 계약 수 결정은 사용자 몫입니다.

## 5단계 — 채점: 이 시스템이 실제로 나아지게 하는 부분

**채점되지 않는 시그널은 운세입니다.** 보통 빠지는 부분인데, 여기가 v2 고도화의
연료 전부이므로 v1 스키마에 처음부터 들어갑니다.

발생한 모든 시그널은 **그 시점의 입력 스냅샷과 함께** 저장됩니다 — 레짐, 디텍터
여섯의 개별 점수, 사용된 가중치, 지표값, 계획 숫자. 그리고 이후 캔들이 들어올 때마다
미채점 시그널을 자동 채점합니다.

| 결과 | 판정 |
| --- | --- |
| `T2` | 목표2 도달 (+2R) |
| `T1` | 목표1 도달 후 손절 본전 이동 (+1R) |
| `STOP` | 손절 (-1R) |
| `EXPIRE` | 유효시간 내 진입 구간 미도달 또는 무승부 (0R) |

함께 기록하는 두 값이 특히 중요합니다.
- **MFE** (최대유리변동) — "목표가 너무 멀었나?"
- **MAE** (최대불리변동) — "손절이 너무 타이트해서 털린 뒤 갔나?"

이게 쌓이면 시그널 탭이 답할 수 있는 것:
- 종목별·레짐별·시간대별 적중률과 **기대값** (승률×평균이익 − 패율×평균손실)
- **디텍터별 성적** — "돌파 디텍터는 원유에서 승률 38%" → 2단계 가중치를 내릴 근거
- "MAE 중앙값이 0.9 ATR인데 손절이 1.2 ATR" → 손절폭 조정 근거

승률이 아니라 **기대값**을 1급 지표로 씁니다. 승률 40%에 기대값 +0.4R인 시스템이
승률 65%에 기대값 -0.1R인 시스템보다 낫습니다.

## 단계별 고도화

| 버전 | 범위 |
| --- | --- |
| **v1** | 게이트 + 레짐 + 디텍터 6 + 합성 + 거래계획. 가중치는 손으로 정한 값. 알림 없음 |
| **v2** | 자동 채점 + 성적표 + 디텍터별 성적. 여기서 처음으로 가중치를 **데이터 근거로** 고침 |
| **v3** | 경제지표 캘린더 API, BTC 펀딩비·OI 디텍터, 금-DXY 상관 디텍터, 웹푸시 알림 |
| **v4** | 과거 캔들로 규칙을 돌려보는 백테스트 모드. 가중치 탐색 |

## 검증 방법

시그널 로직은 눈으로 봐서 맞는지 알 수 없습니다. 그래서 코드를 쓸 때부터:

- 모든 지표 함수는 **알려진 입력/출력 쌍으로 단위 테스트** (TradingView 값과 대조)
- 디텍터는 **합성 캔들**로 테스트 — 완벽한 상승추세, 완벽한 박스, 급락에서 각각
  예상한 부호가 나오는가
- 엔진은 **과거 구간 리플레이**로 테스트 — 지난주 캔들을 봉 단위로 먹여서 나온
  시그널을 차트 위에 찍어보면 대부분의 논리 오류가 눈에 보입니다
