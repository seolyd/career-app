## 0. 한 줄 정의와 사이트의 역할

| 항목 | 내용 |
| --- | --- |
| 사이트 한 줄 정의 | "머무는 기간과 목적에 따라 필요한 것을 챙겨주는 섬 숙소"의 **이야기를 쌓는 블로그형 브랜드 사이트** |
| 1차 목표 (전환) | 트랙을 고르고 **"이 트랙으로 요청하기"** 를 제출하게 만든다 (예약 X, 상담 요청 O) |
| 2차 목표 (신뢰) | 청산도의 계절·사람·체류 기록을 글로 쌓아 "여기서 살아보는 모습"이 그려지게 한다 |
| 3차 목표 (검색) | "청산도 한달살기", "섬 워케이션", "아이와 방학살이" 등 롱테일 검색 유입을 블로그 글로 확보 |
| 하지 않는 것 | 실시간 예약·결제·객실 캘린더. 모든 CTA는 **문의 / 요청** 으로 통일 |

**왜 블로그형인가**
장기체류(7~30박)는 충동 구매가 아니라 "상상 → 비교 → 확신"의 긴 검토를 거칩니다. 상품 페이지 몇 장보다 *"14박 워케이션 가족의 하루"* 같은 글 한 편이 설득력이 큽니다. 그래서 사이트는 **매거진(글) + 트랙(상품) + 요청(전환)** 세 축으로 구성하고, 모든 글의 끝이 관련 트랙 요청으로 이어지게 설계합니다.

### 2.1 하단 탭바 (모바일 전용 · 전역 내비게이션)

엄지 영역 설계. 5개 이하로 고정합니다.

| 탭 | 아이콘 | 이동 |
| --- | --- | --- |
| 홈 | 파도 | `/` |
| 트랙 | 6분할 원 | `/tracks` |
| 저널 | 펼친 책 | `/journal` |
| 섬 생활 | 지도 핀 | `/island` |
| **요청하기** | 배(ferry) — 강조색 | `/request` |

데스크톱(≥1024px)에서는 탭바가 사라지고 상단 고정 헤더(로고 좌측 · 메뉴 중앙 · "요청하기" 버튼 우측)로 전환됩니다.

### 2.2 URL·전환 연결 규칙

- 모든 트랙 페이지·글·방학살이 페이지의 CTA → `/request?track=workation&nights=14` 처럼 **트랙과 기간이 미리 선택된 상태**로 폼 진입
- 글(Journal)은 frontmatter에 `relatedTracks`를 가지며, 글 하단에 해당 트랙 카드 + 요청 버튼 자동 삽입
- 방학살이는 `?track=family&package=vacation-14` 형태

### 3.3 글 상세 화면 요소

1. 상단 읽기 진행 바 (스크롤 연동, CSS만으로 구현)
2. 커버 → 카테고리 칩 · 제목 · 읽는 시간 · 날짜
3. 본문 (한 줄 최대 34~36자 / 모바일, 행간 1.8)
4. 글 끝: 관련 트랙 카드 → "이 트랙으로 요청하기"
5. 이전/다음 글, 같은 카테고리 추천 3개
6. 공유 버튼 (Web Share API → 미지원 시 링크 복사)

### 3.4 목록 화면

- 모바일: 1열 카드 피드, 첫 글은 대형 커버 카드
- 태블릿: 2열 / 데스크톱: 매거진식 비대칭 그리드 (대 1 + 소 4)
- 상단 카테고리 칩 가로 스크롤 (스크롤 스냅), 선택 시 View Transition으로 목록 교체
- 무한 스크롤 대신 "더 보기" 버튼 (SEO·푸터 접근성)

### 5.1 Stay Longer 슬라이더 ★

## 6. 문의 · 트랙 요청 기능 (핵심 전환)

### 6.1 원칙

- **예약이 아니다.** 날짜 확정·결제 없음. 버튼과 문구는 모두 "요청하기 / 상담 요청"
- 하나의 폼(`/request`)이 두 가지 의도를 모두 받음: **① 트랙 요청** ② **일반 문의**
- 입력은 최소화: 필수 항목은 5개 이하
- 어디서 들어오든 트랙·기간·패키지가 **미리 채워진 상태**

### 6.2 폼 흐름 (모바일: 단계형 4스텝, 데스크톱: 한 화면 2열)

상단에 진행 표시(● ● ○ ○). 각 단계는 한 화면에 들어오게.

**Step 0 — 의도 선택**
- `트랙으로 머물고 싶어요` / `그냥 궁금한 게 있어요`
- "궁금한 게 있어요" 선택 시 → Step 3(연락처+문의 내용)로 바로 이동

**Step 1 — 트랙 선택** *(필수, 복수 선택 가능 · 최대 2개)*
- 6개 트랙 + ⭐방학살이 카드형 라디오/체크 (사진 썸네일 + 추천 기간)
- 워케이션 + 패밀리 조합 선택 시 안내: "방학살이 패키지로 받아보시겠어요?" 제안 칩

**Step 2 — 머무는 방식**
| 필드 | 형태 | 필수 |
| --- | --- | --- |
| 희망 기간 | 칩: 2박 · 3박 · 7박 · 14박 · 30박 · 미정 | ● |
| 희망 시기 | 월 선택 칩(예: 2026년 12월) + "날짜가 정해졌어요" 토글 시 대략적 날짜 입력 | ● |
| 인원 | 성인 스테퍼 / 아이 스테퍼 → 아이 수만큼 나이 선택 | ● |
| 관심 옵션 | 해양치유 할인 · 바다학교 · 자전거 · 모니터 세트 · 반려동물 문의 등 체크 | — |

**Step 3 — 연락처와 메시지**
| 필드 | 형태 | 필수 |
| --- | --- | --- |
| 이름 | 텍스트 | ● |
| 연락 방법 | 세그먼트: 전화/문자 · 카카오톡 · 이메일 | ● |
| 연락처 | 선택한 방법에 맞는 입력 (tel/email 키패드 자동 전환) | ● |
| 하고 싶은 말 | 자동 높이 텍스트영역, 플레이스홀더 "예: 오전엔 화상회의가 많아요" | — |
| 개인정보 수집·이용 동의 | 체크 + 내용 펼치기 | ● |
| 마케팅 수신 동의 | 체크 | — |

**Step 4 — 확인**
- 요약 카드 ("Workation · 14박 · 2026년 12월 · 성인 1") + 수정 링크
- 제출 버튼: "이 내용으로 요청하기"

**완료 화면 `/request/done`**
- 접수번호 (예: `CRH-2612-0042`)
- "24시간 안에 ○○으로 연락드릴게요" + 다음 단계 3단계 (상담 → 일정·가격 안내 → 확정)
- 기다리는 동안 읽을 관련 글 3개
- 카카오 채널 추가 버튼

### 6.3 UX 디테일

- 입력 중 이탈 대비: 작성 내용 브라우저 임시 저장 (다시 오면 "이어서 작성할까요?")
- 실시간 검증은 blur 시점에만, 에러 문구는 필드 바로 아래 한 줄
- 모바일 키보드: `inputmode`, `autocomplete="name|tel|email"` 지정
- 제출 중 버튼 로딩 상태, 중복 제출 방지
- 네트워크 실패 시: 입력 유지 + "다시 보내기" + 대체 수단(카카오/전화) 노출
- 스팸 방지: 허니팟 필드 + 서버 측 레이트 리밋 + (필요 시) Cloudflare Turnstile — 사용자 체감 CAPTCHA 없음

### 6.4 제출 이후 운영 흐름 (백오피스는 최소화)

```
[사이트 폼] → [서버리스 함수 /api/request]
                ├─ 입력 검증(스키마) · 스팸 필터
                ├─ 저장: Google Sheets 또는 Supabase(권장) 테이블
                ├─ 운영자 알림: 이메일 + (선택) 카카오 알림톡/텔레그램/슬랙
                └─ 고객 확인: 이메일 선택 시 접수 확인 메일 자동 발송
```

- 1단계(런칭): 저장소는 **Google Sheets** (운영자가 가장 쉽게 봄) 또는 Supabase + 간단 관리 화면
- 상태 컬럼: `접수 → 연락함 → 상담중 → 확정 → 보류/종료` (운영자가 시트에서 직접 변경)
- 저장 데이터: 접수번호, 일시, 의도, 트랙, 패키지, 기간, 희망 시기, 인원/아이 나이, 옵션, 이름, 연락 방법, 연락처, 메시지, 유입 경로(UTM, referrer, 진입 페이지), 동의 여부
- 개인정보: 수집 항목 최소화, 보관 기간 명시(예: 상담 종료 후 1년), 처리방침 페이지 필수

| 원칙 | 기준 |

| 파도처럼 | 이징은 `cubic-bezier(0.22, 1, 0.36, 1)` 계열, 튕김(bounce) 금지 |
| 느리게, 짧게 | UI 반응 150~250ms / 장면 전환 400~700ms |
| 스크롤이 주인 | 자동 재생 애니메이션 최소화, 스크롤 진행에 연동 |
| 존중 | `prefers-reduced-motion` 시 모든 패럴랙스·모핑 비활성, 페이드만 |

### 7.6 이미지·영상 가이드

- 사진 톤: 자연광, 살짝 낮은 채도, 따뜻한 화이트밸런스. 사람은 뒷모습·손 위주
- 필수 촬영 리스트: 트랙별 시그니처 세트 6컷, 리셋 박스, 객실 창밖 뷰, 슬로길/돌담/구들장논, 아이 탐험 장면(초상권 동의), 계절별 바다
- 포맷: AVIF → WebP 폴백, 반응형 `srcset`, 첫 화면 외 지연 로딩, LQIP(흐린 미리보기)
- Hero 영상: 6~8초 루프, 1.5MB 이하, 모바일 데이터 절약 모드(`Save-Data`)면 정지 이미지

## 8. 적용할 최신 CSS / JS 기능

원칙: **Progressive Enhancement** — 최신 기능은 "있으면 더 아름답게", 없어도 모든 기능은 동작.

### 8.1 CSS

| 기능 | 사용처 |
| --- | --- |
| **Scroll-driven Animations** (`animation-timeline: scroll()/view()`) | Hero 영상 축소, 텍스트 리빌, 읽기 진행 바, 섹션 등장 — JS 없이 |
| **View Transitions** (same-document + cross-document `@view-transition`) | 트랙 카드→상세 모핑, 카테고리 필터 전환, 폼 스텝 전환 |
| **Container Queries** (`@container`, `cqi` 단위) | 트랙 카드·글 카드의 자기 크기 기반 반응형 |
| **`:has()`** | 폼에서 트랙 선택 상태에 따라 부모 카드/요약 스타일 변경, 오류 필드 강조 |
| **CSS Nesting** | 스타일 구조화 |
| **`@layer`** | reset / tokens / base / components / utilities 계층 관리 |
| **OKLCH + `color-mix()` + `light-dark()`** | 색 토큰, 다크모드, 트랙 액센트 파생색 |
| **`@property`** | Stay Longer 배경 그라디언트의 부드러운 색 보간 |
| **`@starting-style` + `transition-behavior: allow-discrete`** | 팝오버·다이얼로그·바텀시트 등장/퇴장 애니메이션 |
| **Anchor Positioning** | 시그니처 세트 핫스팟 툴팁, 지도 핀 팝오버 |
| **Scroll Snap** | 트랙 캐러셀, 카테고리 칩 |
| **`field-sizing: content`** | 문의 메시지 텍스트영역 자동 높이 |
| **`text-wrap: balance / pretty`** | 제목·본문 줄바꿈 품질 |
| **Subgrid** | 카드 그리드 내부 정렬 (제목/배지/버튼 라인 맞춤) |
| **`interpolate-size: allow-keywords`** | FAQ 아코디언 `height: auto` 애니메이션 |
| **`dvh` / `svh` 단위, `env(safe-area-inset-*)`** | 모바일 풀스크린 Hero, 아이폰 하단 탭바 안전 영역 |

### 8.2 HTML / JS / Web API

| 기능 | 사용처 |
| --- | --- |
| **Popover API** (`popover`, `popovertarget`) | 핫스팟 설명, 공유 메뉴 — JS 최소 |
